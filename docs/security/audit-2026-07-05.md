# Auditoría de Seguridad — 2026-07-05

**Auditor:** AppSec + Cloud Architect (assessment exhaustivo VPS + app + IA)
**Alcance:** Infraestructura VPS, aplicación Next.js, integración de IA (Vercel AI SDK).
**Método:** Inspección directa por SSH del VPS + análisis estático del código (2 barridos verificados).

## Veredicto general

Postura **sólida** en la capa de aplicación web y red (JWT RS256 verificado, guard ESLint anti-IDOR, SQL 100% parametrizado, HMAC de webhook con anti-replay, cache de Key Vault cifrado AES-256-GCM, CSP/HSTS completos, Cloudflare delante). Los riesgos **CRÍTICOS reales** están en la capa de IA (aislamiento multi-tenant y keys en texto plano) y en el hardening del host. **Ningún IDOR vivo, ningún secreto en el repo, ninguna inyección SQL.**

## Confirmaciones positivas (revisado, sin hallazgo)

- Verificación JWT RS256 completa contra JWKS de Entra: issuer/audience allow-list que falla cerrado, exp/nbf con skew, `tid` del token verificado (nunca del cliente).
- SQL 100% parametrizado; las rutas "dinámicas" solo interpolan nombres de columna desde allow-lists.
- Ningún IDOR vivo (re-verificación manual de rutas que leen `tenantId` del body).
- Salida del LLM renderizada con `react-markdown` sin `rehype-raw` (HTML inerte).
- Ninguna key de IA client-side (`NEXT_PUBLIC_*`).
- Cache de Key Vault cifrado AES-256-GCM, IV random, auth tag, modo `0o600`, secretos no logueados.
- Headers de seguridad completos: HSTS+preload, `frame-ancestors 'none'`, X-Frame-Options DENY, nosniff, Permissions-Policy restrictiva.
- SSO con state HMAC-firmado (CSRF correcto); webhook Paddle con anti-replay + `timingSafeEqual`.
- MySQL y Redis solo en loopback; Docker daemon no expuesto; UFW activo (22/80/443); fail2ban activo.

## Remediaciones aplicadas en este ciclo

1. **IA-1** (CRÍTICO): aislamiento del cache de IA por tenant. Commit `security(ai): aislar cache de IA por tenant`.
2. **A-1** (ALTO): eliminado stored XSS en FinOps Academy. Commit `security(xss): eliminar dangerouslySetInnerHTML`.
3. **V-1/V-2/V-4/V-6** (VPS): hardening SSH (password auth off, root prohibit-password, X11 off) vía drop-in `/etc/ssh/sshd_config.d/99-hardening.conf` + neutralización de `50-cloud-init.conf`; `.env` a `chmod 600`. Verificado con conexión nueva por key (sin pérdida de acceso).
4. **IA-2** (CRÍTICO): API keys de IA cifradas en reposo con AES-256-GCM (`src/lib/secretCrypto.ts`, formato `enc:v1:iv:tag:ciphertext`, clave maestra `MFA_ENCRYPTION_KEY`). Cifrado al escribir (`admin/config/ai` PATCH), descifrado al leer (`getAIConfig`) con fallback transparente a plaintext legacy. Columna `Tenants.ai_api_key` ampliada a VARCHAR(1024) (migración `20260705-003`). Script `scripts/encrypt-existing-ai-keys.ts` para cifrar keys ya existentes en prod.
5. **IA-7** (MEDIO, de paso): el PATCH de config IA ahora invalida el cache in-memory de config (`invalidateAIConfigCache`), eliminando la ventana de ~5 min usando la key vieja tras una rotación.

### Tercera tanda (código, sin downtime)

1. **IA-3** (ALTO): prompt injection mitigado en el copilot — datos no confiables (payload de tenant, pageContext, pregunta) movidos del `system` al mensaje de usuario con delimitadores `<context_data>`/`<user_question>` e instrucción explícita de tratarlos como datos, no instrucciones.
2. **IA-4** (ALTO): rate limiting por (tenant, usuario) en todos los endpoints de IA — copilot 15/min, ai-report/assessment/upload 5 cada 5 min. Corta denial-of-wallet.
3. **A-4** (MEDIO): rate limiter con backend Redis (`checkByKeyDistributed`, INCR+PTTL atómico) con **fallback transparente a memoria** si Redis no responde. Aplicado a IA, `checkout` y `sso/start` (throttle pre-login por IP).
4. **A-6** (BAJO): helper `serverError` (`src/lib/apiErrors.ts`) que loguea el error server-side y omite `details` en producción; reemplazado el patrón `details: error.message` en 18 handlers.
5. **IA-6** (MEDIO): validación de formato UUID de `subscriptionId` antes de interpolarlo en el KQL de `sustainability` (previene inyección KQL).
6. **A-3** (MEDIO): CSP nonce + `strict-dynamic` desplegada en modo **Report-Only** (`src/proxy.ts`, compuesta con el middleware de next-intl). No bloquea; observa violaciones para validar antes de promover a enforcing y quitar `unsafe-inline`.
7. **IA-5** (MEDIO): marcador DLP documentado en `aiProvider.ts` (redacción/tokenización de PII pendiente de decisión de producto).
8. **A-2** (ALTO): **riesgo aceptado** — `thrift` sin fix upstream; path parquet solo alcanzable vía endpoints AWS con `requireTenantRole(ADMIN/OWNER)`, input semi-confiable, feature AWS oculta.
