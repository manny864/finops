# Showback/Chargeback PDF Generation

## Overview

The FinOps SaaS platform supports server-side generation and delivery of professional Showback/Chargeback PDF invoices. This feature is built using `@react-pdf/renderer` for pure JavaScript PDF generation (no Chromium), making it suitable for serverless environments.

## Architecture

### Server-Side Rendering

- **Framework**: `@react-pdf/renderer` (Node.js-native PDF generation)
- **Template**: React components that render to PDF
- **Storage**: PDFs are generated on-demand and streamed directly to the client
- **Delivery**: Single PDF or ZIP archive with multiple customer PDFs

### Key Components

1. **PDF Template** (`src/lib/pdf/showbackInvoice.tsx`)
   - React components using @react-pdf/renderer
   - A4 page size, professional styling
   - Multi-page support for large datasets

2. **API Endpoints**
   - `GET /api/admin/report/invoicing` - Extended to support `format=pdf`
   - `POST /api/admin/report/invoicing/email` - Email delivery via Microsoft Graph

3. **Frontend** (`src/components/dashboard/InvoicingReportPanel.tsx`)
   - Download buttons for individual PDFs
   - ZIP download for all customers
   - Email dialog integration

## API Usage

### Single Customer PDF Download

```bash
curl -X GET \
  'https://app.finops.local/api/admin/report/invoicing?tenantId=TENANT_ID&period=2026-06&format=pdf&customerId=CUSTOMER_ID' \
  -H 'Authorization: Bearer <TOKEN>' \
  -o showback-CUSTOMER_ID-2026-06.pdf
```

**Response:**
- Content-Type: `application/pdf`
- Content-Disposition: `attachment; filename="showback-{customerId}-{period}.pdf"`

### All Customers ZIP Download

```bash
curl -X GET \
  'https://app.finops.local/api/admin/report/invoicing?tenantId=TENANT_ID&period=2026-06&format=pdf' \
  -H 'Authorization: Bearer <TOKEN>' \
  -o showback-2026-06.zip
```

**Response:**
- Content-Type: `application/zip`
- Content-Disposition: `attachment; filename="showback-{period}.zip"`

### Email PDF Delivery

```bash
curl -X POST \
  'https://app.finops.local/api/admin/report/invoicing/email' \
  -H 'Authorization: Bearer <TOKEN>' \
  -H 'Content-Type: application/json' \
  -d '{
    "tenantId": "TENANT_ID",
    "period": "2026-06",
    "customerId": "CUSTOMER_ID",
    "recipientEmail": "customer@example.com",
    "recipientName": "John Doe"
  }'
```

**Response:**
```json
{
  "success": true,
  "message": "Email sent successfully"
}
```

## Authentication & Authorization

- All endpoints require Bearer token authentication
- Tokens must have `tid` (tenant ID) claim
- User must have ADMIN role in the tenant (checked via `requireTenantRole`)
- SuperAdmins (@cscloudsolutions.com.ar) bypass role checks
- Mock tenants bypass full authentication

## Email Integration

### Microsoft Graph sendMail

- Requires `AZURE_SENDER_EMAIL` or `CONTACT_EMAIL_SENDER` environment variable
- Requires valid Azure AD client credentials (`AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`)
- PDF is base64-encoded and attached to the email
- Subject line: `Showback Report - {customerName} - {period}`
- Email body includes:
  - Summary table (original cost, markup %, adjusted cost)
  - Professional branding
  - Generation timestamp

### Fallback Behavior

If `AZURE_SENDER_EMAIL` is not configured:
- Email endpoint returns 503 error
- Admin is notified to configure the sender email

## Audit Logging

Every PDF generation creates an `ActionLogs` entry:

```sql
INSERT INTO ActionLogs (
  tenant_id,
  action_type,
  resource_id,
  status,
  user_email
) VALUES (
  'TENANT_ID',
  'SHOWBACK_PDF_GENERATED',
  'customerId:period' OR 'all:period',
  'SUCCESS' OR 'FAILED',
  'user@example.com'
);
```

Email delivery creates an entry with `action_type = 'SHOWBACK_PDF_EMAIL'`.

## Data Precision (Regla Cero)

All monetary amounts are handled with precision:
- Database: `DECIMAL` type
- Calculations: Multiplied by 100 to work with integers, then divided by 100
- Formula: `adjustedCost = Math.round(originalCost * (1 + markupPercent/100) * 100) / 100`

## Troubleshooting

### PDF Generation Fails

**Symptom**: 500 error with "Failed to generate PDF"

**Causes**:
- Missing or invalid line items
- Memory exhaustion for very large datasets
- @react-pdf/renderer runtime error

**Fix**:
- Check CostSnapshots table for the period
- Verify markup_percentage in Tenants table
- Check server logs for detailed error

### Email Not Sent

**Symptom**: 503 error or "Sender email not configured"

**Fix**:
```bash
export AZURE_SENDER_EMAIL="noreply@yourdomain.com"
# or
export CONTACT_EMAIL_SENDER="noreply@yourdomain.com"
```

**Symptom**: "Failed to authenticate with MS Graph"

**Fix**:
- Verify `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`
- Check Azure app registration has `Mail.Send` permission
- Confirm sender email is a valid Exchange mailbox

### ZIP Generation Issues

**Symptom**: Corrupted or empty ZIP

**Fix**:
- Ensure all customers have at least one line item
- Check disk space on server
- Verify jszip is installed: `npm list jszip`

## Performance

- **Single PDF**: ~500ms (includes PDF generation)
- **ZIP (3 customers)**: ~1.5s (parallel PDF generation)
- **Memory**: ~50MB per 10,000 line items

For optimal performance with large numbers of customers, consider batching email sends or implementing a queue system.
